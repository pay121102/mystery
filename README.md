# シナリオ矛盾チェッカー (無料版)

マーダーミステリー・TRPG のシナリオ制作用ツールです。人物 × 時刻の時系列表を作ると、アリバイや証言の矛盾を自動で見つけます。

- ブラウザだけで動きます (インストール不要、ビルド不要、外部 CDN なし)
- **通信は一切しません**。データはそのブラウザの中 (localStorage) と、書き出した JSON ファイルにだけ残ります
- 無料版に機能の制限はありません

**公開ページ: https://pay121102.github.io/mystery/** (無料版 v0.1.0)

- [利用条件](terms.html)
- 感想・不具合の報告: [GitHub の報告ページ](https://github.com/pay121102/mystery/issues/new/choose) (GitHub のアカウントが必要です。書いた内容は誰でも見られるので、未発表のシナリオの中身は書かないでください)

## 使い方

1. `index.html` をダブルクリックしてブラウザで開きます (Chrome / Edge / Firefox / Safari の最新版)
2. 初めて開いたときはサンプル「雪鳴館の殺人」が入っています。右側 (スマホでは上) に矛盾の警告が並びます
3. 「新規作成」で白紙から始めます

### 画面

| タブ | できること |
|---|---|
| 時系列表 | マスを押して、その時刻にいた場所と行動を入れます。1 マスに複数の行動を入れられます |
| 証言 | 「誰が、誰を、いつ、どこで見たか」を入れます。証言者と見た相手を同じにすると、本人のアリバイの主張として扱います |
| 手がかり | 手がかりごとに、知ることになる人物にチェックします。「秘密」の印も付けられます |
| 人物・時刻・場所 | 人物・時刻・場所の追加と並べ替え、場所に入れる人の限定・閉鎖時刻、場所の間の移動時間 |

### 矛盾チェックのルール

| ルール | 種類 | 内容 |
|---|---|---|
| 同じ時刻に複数の場所にいる | 矛盾 | 1 つのマスに、別々の場所の行動が入っている |
| 移動時間が足りない | 矛盾 | 前の時刻の場所から次の場所まで、時刻の差より移動時間が長い。空いたマスは飛ばして前後を比べます |
| 立ち入れない場所への出入り | 矛盾 | 「入れる人」を限定した場所に他の人がいる / 閉鎖中の時刻に誰かがいる |
| 証言と行動の食い違い | 矛盾 | 証言の場所と、見られた人物の時系列表の場所が違う |
| 目撃者がその場にいない | 矛盾 | 証言者自身がその時刻に別の場所にいる |
| 証言の裏付けがない | 注意 | 見られた人物のその時刻の行動が未入力 |
| 誰も知らない手がかり | 注意 | 誰にもチェックが付いていない手がかり |
| 全員が知っている秘密 | 注意 | 「秘密」の手がかりを全員が知っている |
| 時刻の書式・並び | 注意 | 「21:30」の形で読めない時刻、前の行と同じ時刻 |

- 警告を押すと、該当するマス・証言・手がかりに移動します。該当するマスは赤 (矛盾) か黄 (注意) で囲まれます
- 時刻は「その時点でそこにいた」という意味です。移動時間は、隣り合う場所の間だけ入れれば経由する道の合計で計算します。どこともつながっていない場所は「未設定のときの移動時間」を使います
- 前の行より早い時刻は日付をまたいだとみなします (23:45 → 0:00)
- 犯人の嘘など、**わざと食い違わせた証言**は「意図的な嘘」にチェックすると警告されません。窓越しに見た場合などは「離れた場所から見た」にチェックすると、目撃者の居場所を確かめません

### 保存

- 入力するたびにブラウザへ自動で保存されます (同じブラウザ・同じ場所の `index.html` で開けば続きから)
- ブラウザのデータ消去や、別のパソコン・別のブラウザでは消えます。**大事なシナリオは「JSON 書き出し」でファイルに保存してください**
- 「JSON 読み込み」で書き出したファイルを開くと、内容がそのまま戻ります

## テスト

`tests.html` をブラウザで開くと、矛盾チェックのテストが走ります。「すべて成功」と出れば正常です。サンプルに入れてある矛盾 7 件 (矛盾 5・注意 2) がすべて警告されること、1 つずつ直すとその警告だけが消えること、JSON の書き出し・読み込みで内容が戻ることなどを確かめます。

## GitHub Pages で公開する

1. GitHub で新しいリポジトリを作ります (例: `mystery-checker`、Public)
2. この `mystery` フォルダの中身 (`index.html`, `style.css`, `tests.html`, `terms.html`, `js/`, `README.md`, `.github/`) をリポジトリの一番上に置いてコミットします。ブラウザだけで行う場合は、リポジトリの画面で「Add file → Upload files」にフォルダの中身をドラッグします
3. リポジトリの「Settings → Pages」を開き、「Build and deployment」の Source を「Deploy from a branch」、Branch を `main` / `/ (root)` にして Save します
4. 1〜2 分待つと `https://<ユーザー名>.github.io/<リポジトリ名>/` で開けます。テストは同じ URL の末尾に `tests.html` を付けて確認できます

注意:

- GitHub Pages に置いても、データは見ている人のブラウザにだけ保存されます。サーバーには何も送られません
- localStorage は「サイトごと」に分かれます。ダブルクリックで開いたものと GitHub Pages で開いたものは、別々の保存場所です。移すときは JSON 書き出し → 読み込みを使ってください
- 同じ `github.io` のユーザー名の下に置いた別のページとは保存場所を共有します (保存名は `mystery-scenario-checker:v1`)

## ファイル構成

| ファイル | 役割 |
|---|---|
| `index.html` / `style.css` | 画面 |
| `js/model.js` | データの形、JSON 読み込み時の検証 |
| `js/checker.js` | 矛盾チェック (画面に依存しない) |
| `js/sample.js` | サンプルシナリオと、その期待される警告 |
| `js/app.js` | 画面の動き、自動保存、書き出し・読み込み |
| `tests.html` / `js/tests.js` | テスト |
| `terms.html` | 利用条件 |
| `.github/ISSUE_TEMPLATE/` | 感想・不具合の報告フォーム |

ES モジュールは使っていません (ダブルクリックで開いたときに読み込めないため)。
